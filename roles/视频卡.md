# 视频卡起草（subagent 角色）

输入：`reports/<date>/口播稿.md`（定稿版）+ `reports/<date>/daily.json`。
输出：`reports/<date>/video/视频卡.json`（或主 agent 指定的路径）。

结构 `{"date_label": "7 月 21 日", "cards": [...]}`：
- 第一张固定封面：`{"image": "视频卡.横屏.png", "title": "封面", "anchor": null}`。
- 之后按**口播稿叙述顺序**每个主题一张卡；短讯、乐子、预测市场各自合并成一张。
- 用户在口播稿里自己发挥的议论若自成段落，单独成卡。

字段：
- `title`：≤15 字，用 daily.json 标题或口播稿的说法。
- `color`：按主题所属分区取——行业 `#A8562F` / 深度 `#4E7CA1` / 论文 `#3F8E7E` / 监管 `#8A6FA8` / 官方 `#7C8894` / 乐子 `#C2703C` / 赔率 `#5E8C5A` / 用户议论卡 `#C2703C`。
- `anchor`：该主题在口播稿里第一句的**开头原文片段**，6~12 字，全稿唯一。烧录时忽略标点空格后在单条字幕内做包含匹配，而字幕按短语切行——所以 anchor 必须逐字照抄且**不能含逗号/分号**（不跨短语），太长宁可截短。
- `bullets`：2~4 条，每条 ≤22 字，只写关键事实和数字，措辞平实（用户会自己改）。**4 条是上限也是安全值**（和两行字幕兼容，只是轻微接触），5 条才会被字幕压住，所以不必为了避让字幕主动压到 3 条。
