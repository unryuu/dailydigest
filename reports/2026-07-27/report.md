## 五、事故与教训

### ⚠️ 5.1 主 agent 用编造的示范数字解释概念，被用户当成真实数据（本期最严重）
指出用户把「0.77 个百分点」写成「0.77 %」时，主 agent 为说明百分点与百分比的区别，写了「失业率从 3.5% 涨到 4.27%」当例子，**未标明这是虚构的示范值**。用户随即要求把这个写法用进成品：「改成『失业率从 3.5% 涨到 4.27%』这种详细描述吧」。

主 agent 回查原文后发现斯坦福简报**从头到尾只给变化量，绝对水平只在 Figure 1 图里、正文一个数都没有**，当场向用户说明数字是自己编的、给了三个可写方案，并明确不发频道直到用户定夺。用户自行改成不用数字的方向表述。

**教训**：agent 在解释性文字里造的任何数字，都可能被用户当成材料。**凡在对话中举例造数，必须当场标「这是编的示范值」。** 这次靠回查原文兜住了，但这是发频道前的最后一道关口，风险很高。

### 5.2 机器崩溃两次，损失一轮 reader
- 第一次崩在 reader group-2（Altman）跑到一半，digest 未落盘，重派。
- 第二次崩在 reader group-4（就业）跑到一半。
- 用户诊断：内存不够；第二次后指出**可能是 subagent 又派 subagent**。此后所有派活 prompt **加了「绝对不许派 subagent」的硬规矩**（核查 agent、写手、口播稿三个都加了），未再崩。
- 应对：group-4、group-5 改由**主 agent 自己用 WebFetch / curl 读原文并手写 digest**，绕开派活风险。这两组是「直读直摘」类型，不需要多源交叉核对，自己读代价可接受。

**建议写进 `steps/3-精读.md`**：派活 prompt 必须含「禁止嵌套派 subagent」。

### 5.3 `python` 被 Application Control 拦下
跑到一半 `python` 突然报「已阻止此文件」。查明是 PATH 上排第一的 `C:\Users\mark\AppData\Local\hermes\hermes-agent\venv\Scripts\python` 被系统策略拦，不是 Python 本身出事。**当期所有命令改用 `C:\Users\mark\.venvs\base\Scripts\python.exe` 全路径。**

顺带查清（用户提问）：hermes **没有卸载程序**（控制面板无条目、注册表卸载项为空、hermes-setup.exe 0.0.1 不带卸载信息），无运行进程、无开机自启、无计划任务，占 2.11 GB；它往用户 PATH 写了三条。**关键坑**：PATH 上只有两个 python.exe——hermes 那个和 WindowsApps 的商店占位符，`.venvs\base` **不在 PATH 里**，所以直接删 hermes 会让 python 从「被拦」变成「弹商店」。已给用户「先改 PATH（删三条 hermes + 把 base 提到最前）、再删文件夹进回收站」的两步操作和命令，并提示 `.env` / `auth.json` 可能含凭据（agent 未读）。**用户尚未执行。**
