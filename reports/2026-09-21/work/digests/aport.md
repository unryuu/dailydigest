# Agent 付款前，再加一道权限检查

- 推荐强度：强
- 档位线索：支持已定银牌。可落到“真正执行付款前查权限”的具体机制；应交代作者是产品创始人、实验使用模拟银行。
- 涉及文章：[APort Vault: Benchmarking AI Agent Payment Authorization with the Open Agent Passport](https://huggingface.co/papers/2609.22076) · Uchi Uchibeke，APort Technologies，arXiv · ２０２６－０９－１８提交，本期按０９－２１榜单发现收录。
- 精读依据：`raw/papers/aport-full.txt`，第三节方法、第四节结果与表２至５、第五节攻击分析、第六至十节讨论、限制和披露；日期核对 `raw/extra/aport-arxiv.txt`。

## 核心主张

模型答应转账之后，钱该不该真的转出去，可以由程序再查一次权限。APort 把同一批真人编写的攻击分别交给有无付款前权限检查的 Agent，在可比较的６８９７０组条件中，单靠模型出现１０５次向未获准收款人转账，加上检查后为零。模型仍然会提出付款请求，获准的付款也照常执行；实验测的是明确的收款人限制能否执行，不是模型是否全面安全。

## 为什么值得看（钩子）

“骗过了 AI”不等于“拿到了钱”。模型生成行动与系统真正放行之间，留一个明确检查收款人的关口，就能在这项实验中挡住最后一步。

## 关键细节／引述

- 研究来自一场模拟银行攻防活动，共收集４３７１条真人攻击，回放到八家机构的１４个模型，分单轮和多轮上下文、有无检查层等条件，完成２２５９６４次评估。没有真实资金移动。两种架构保持模型、提示词、工具格式等相同，差别是转账工具执行前是否按权限规则检查。
- 核心只看第２—４级：规则允许向特定名单收款人付款，并限制其他人。全部已完成样本中，单靠模型出现１４０／７６８４２次违规收款人转账，加检查后为０／６９２９７；由于样本覆盖不同，更干净的对照是模型、攻击和回放方式匹配的６８９７０组，其中１０５对零。正文优先用匹配对照，勿把不同分母直接称为同样次数测试。
- 检查层并未把所有付款封死：有２５３７０次评估仍出现成功付款。它检查的２５６４０次转账调用中拒绝１８７次，其中１４８次因收款人不获准，其余涉及金额、限额或审计代码；调用次数与评估次数不是同一分母。
- 第４级约７９.４％评估出现付款请求，不能写成约八成被攻破。该级本就要求处理带有效审计码、收款人获准、金额合规的付款；８０９条提示让全部１４个模型都付款时，收款人都是名单内地址。反过来，收款人在名单内也不能证明业务目的真实，论文没有裁定请求者资格和业务正当性。
- 一类攻击伪造“收款人已经验证”的回执，贡献了第２级多轮单靠模型条件下１１３次越权结果中的１１１次，涉及七个模型。执行前检查不看聊天记录里声称已验证什么，仍按真实收款人与实际名单判断，因此这类攻击在检查层后没有造成越权转账。
- 边界：这是单工具、模拟支付域的研究，不能直接推广到代码执行或数据访问。零次观察不保证真实风险为零，按７９０个来源会话估计的上界为０.３８％；策略写错、授权过宽或检查可被绕过仍会失败。作者是这套检查产品的创始人，部分多轮条件未完成，人工验证切片缺失，且第４级本地实现比公开规则包多一道审计码检查。第５级本就没有付款权限，其零结果不能拿来夸大抗攻击效果。
