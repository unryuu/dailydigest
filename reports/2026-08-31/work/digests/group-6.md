# OpenClaw 把会话和工作区一起搬到设备或云端

- 推荐强度: 强
- 档位线索: 够银，不建议金。真正的新意是把会话执行位置和工作区放到配对设备或云端工作机，而不是首次支持连接远程设备；正文应收窄到这条主线，避免被超长更新列表冲散。
- 涉及文章: [OpenClaw 2026.8.1](https://github.com/openclaw/openclaw/releases/tag/v2026.8.1) · OpenClaw／GitHub Release · 2026-08-31

## 核心主张
2026.8.1 把重点能力命名为「Sessions beyond your Gateway」：工作可以在配对设备或云端工作机上运行，会话的工作区也随之移动，并可复用已经预热的机器和项目种子。它与同一份 Release 中的「Node-hosted tools」是两个层次：后者是在配对节点发现并调用获批的插件工具和 MCP 服务，前者则把会话的执行落点与工作区一起放到 Gateway 之外。围绕这条主线，OpenClaw 还补齐了设备托管、云机器休眠恢复、工作区冲突提示和远端附件传递。

## 为什么值得看（钩子）
这不是「Agent 又多连了一台远程电脑」，而是 Agent 的会话、代码工作区和执行机器开始被当成可调度、可回收的整体。它让本地 Gateway 更像控制平面，配对电脑和临时云机器则变成可选择的会话运行位置。

## 关键细节 / 引述
- Release 的原话是：在配对设备或云端工作机上运行工作，「move the session workspace with it」，并为之后的云会话复用预热机器和项目种子。
- 配对机器可以主动加入会话托管；官方提供一次粘贴式接入流程，macOS 应用也能原生开启 session hosting。
- 云端工作机可在空闲一段时间后暂停；下一条消息到来时再分配替代机器，同时保留会话和经过对账的工作区。
- 云端工作区发生冲突时，Control UI 会显示 staged-ref 指引、限定范围的冲突路径和结构化事件；如果系统保留了本地版本，侧栏会明确提示，而不是静默覆盖。
- 远程会话现在可以收到图片和 PDF，准备好的输入会在云端 placement 过程中保留；同步时还会双向排除 Python 缓存、依赖目录和 macOS 元数据，避免缓存改写妨碍结果回收。
- 这版同时默认开启三项长期记忆／自学习能力：符合条件的私人对话召回、带来源限定的后台记忆整理与 Dream Diary，以及自动吸收通过扫描的新技能；另有不把秘密写入聊天或模型上下文的私密凭证请求。升级还包含两项破坏性迁移：移除内置 OpenProse，并把随附的 `codex/*`、`openai-codex/*` 路由迁到 `openai/*`。

## 与近期的关系
重复风险较高：远程节点、远程工具和桌面控制此前已是 OpenClaw 的既有叙事，如果标题仍写「连接远程设备」就会把旧能力误报成新品。本次应只写 Release 明确新增的会话托管、工作区随执行位置移动、云机器生命周期和冲突回收机制；长期记忆、技能自学与凭证请求可作为大版本旁证，不要各自扩成另一条主线。
