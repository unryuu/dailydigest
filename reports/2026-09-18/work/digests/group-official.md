## Claude 把三十多个生物模型平均提速约四倍

- 推荐强度：强，本组第一。
- 档位线索：够金。它不只是一次科研演示，而是四周内把三十多个开源模型改快、把代码全部开放，并把此前蛋白设计流程的算力降了两个数量级。正文需把「准确折叠一万 token 以上」与「七万 token 只能跑、结果会塌」严格分开。

### 核心主张

Anthropic 让一个内部通用研究模型，在两名生物分子建模员工监督下，改造三十多个结构预测、蛋白设计、蛋白语言和基因组模型。结果是平均约四倍提速，同时把结构模型中最费算力的三角注意力和三角乘法做成可复用内核；所有优化代码已经开放。

另一条增量是内存：Claude 做出的低内存 Big 模式，让单个 NVIDIA GPU 节点能准确预测超过一万 token 的生物分子系统。把这些优化接回此前的蛋白结合物设计流程后，一个 Claude、单张 H200、二十四小时得到的计算机模拟分数，与此前可用子 Agent、最多两千五百小时 H100 的流程相近。

### 为什么值得看（钩子）

Claude 这次没有直接替科学家提出一个结论，而是改造科学家每天使用的三十多个模型。它把原来需要各团队分别投入数周的底层优化，集中在不到四周完成，并交付可复用代码。

### 关键细节／硬数字

- Claude 在不到四周优化了三十多个开源模型，覆盖结构预测、蛋白设计、蛋白语言模型和基因组学；参与监督的是两名熟悉生物分子建模、此前没有推理优化或 GPU 内核工程经验的 Anthropic 技术人员。
- 全组任务平均约四倍提速，精度只小幅下降；要求输出完全一致时，整体仍接近两倍提速。只看十多个结构预测模型，最小精度损失模式约四倍，完全一致模式约 1.6 倍。
- Claude 开发的 FlashPairformer 相对现有行业标准，把三角注意力加速 2.7—2.9 倍，把三角乘法加速 1.7—3.2 倍，具体取决于模型配置。
- 结构预测加速不只依靠通用内核，还包括缓存重复计算、把永远不走的分支化简为常量等逐模型优化；Anthropic 对每个模型检查了下游任务表现。
- Big 模式在单个 GPU 节点上准确预测了超过一万 token 的线粒体复合体 I、TRiC 伴侣蛋白复合体、蛋白酶体和细菌核糖体，结构与实验结果接近。作为对照，文中提到 AlphaFold3 准确预测的 40S 核糖体为 7663 个 token。
- 在单个八卡 B300 节点上，系统还能完成三万一千至七万多个 token 的推理，但这些超大病毒衣壳和蛋白容器预测全部塌缩，只证明内存门槛被推开，不能写成已经准确建模七万 token。
- 新蛋白设计流程只给一个 Claude、一张 H200 和二十四小时，不用子 Agent，也没有人工引导设计。三个 Claude 型号在 16 个目标上的计算机模拟结合分数，与此前最多使用约两千五百小时 H100 的 Mythos 5.1 流程相近；GPU 与模型 token 合计花费约 150 美元。
- Anthropic 同时与 Adaptyv Bio 发起五道蛋白设计题，承诺实验验证超过五千个社区方案，并提供最多一百万美元 Claude 额度和二十五万美元 Modal 算力额度。这是未来验证安排，不是本文优化结果已经通过五千次湿实验。

### 局限

四倍与内核加速均来自 Anthropic 自己的技术报告和测试，正文里没有独立团队复现。所谓「精度只小幅下降」在不同任务上的具体幅度不统一；完全一致输出时的提速也比主标题数字低。新蛋白结合物流程目前只比较计算机模拟分数，不能写成已经复现八月那次湿实验成功率。七万 token 的系统虽然跑通推理，结构预测已经塌缩，准确能力边界仍在一万 token 级别。

### 与近期的关系

8 月 20 日日报已经写过 Claude 为 15 个目标设计蛋白结合物，其中 14 个经实验验证成功。本文不能重讲「Claude 会设计蛋白质」，新增内容是把三十多个开源生物模型平均提速约四倍、用 Big 模式在单节点准确处理一万 token 以上系统，以及把上一轮设计流程从约两千五百 H100 小时压到一张 H200 跑二十四小时。若正文围绕「先改快科研工具，再让自己的科研流程便宜一百倍」展开，重复风险低。

## Astra for Law：给通用 Astra 接上美国法律检索和律所控制层

- 推荐强度：中强。
- 档位线索：够银。Astra 主线近期极密，但法律版有独立产品结构、专用检索和 200 题评测，不应再写模型本体能力或旧安全争议。

### 核心主张

Astra for Law 不是一款重新训练的独立法律模型，官方描述是把 GPT-6 Astra 与法律检索索引、法律分析和写作指令、保密控制及插件组合成一套行业配置。它先向入选律所开放 ChatGPT／Codex Trusted Access，API 随后提供，Harvey 和 Legora 等 API 客户可以把它接进自己的产品。

最硬的能力增量来自专用检索：在相同最高推理档位下，完整法律版在 200 道美国法律研究题上的总体正确率为 54.0％，仅用网页搜索的 GPT-6 Astra 为 38.7％。这说明提升主要来自法律语料、检索和工作流配置，不能写成 Astra 基础模型又升级了一代。

### 为什么值得看（钩子）

OpenAI 把法律产品的竞争点从「模型会不会写备忘录」推进到三件更具体的事：能否找到正确判例和段落、能否把律所自己的方法装进去、能否按案件权限隔离机密资料。

### 关键细节／硬数字

- 法律检索索引覆盖美国判例、成文法、法规、法院规则和行政决定，语料超过 2.3 亿个 URL，每天增加来源。与 Free Law Project 合作接入的 CourtListener 收藏覆盖超过 99.9％ 的美国已公布先例判例。
- OpenAI 用 Vals AI Legal Research Bench 的私有验证集测试 200 道美国法律研究题。最高推理档位下，Astra for Law 总体正确率为 54.0％，GPT-6 Astra 加普通网页搜索为 38.7％，相对提高 40％。
- 在以判例为主的问题上，法律版找到的参考判例多 24％；对一组经过审计的目标段落，在相同推理档位下，从正确判决书中取回的相关段落最多多 54％。
- 初始渠道是入选律所的 Trusted Access，覆盖 ChatGPT 和 Codex；模型选择器中叫 `GPT-6 Astra Law`，API 名为 `gpt-6-astra-law`，官方称 API 即将开放。
- 面向机密业务，符合条件的律所可在 API 使用零数据保留；ChatGPT Enterprise 的使用默认不进入人工审查。OpenAI 还与 Latham & Watkins 设计信息权限、道德墙、客户指令和律所监督机制。
- 首批有 26 个合作伙伴插件，连接 Relativity、Clio、iManage、Intapp、DeepJudge 和 Thomson Reuters 等系统；其中 9 个社区插件带 47 个可改写技能。ChatGPT for Word 同日正式全面开放。
- 官方展示的一个诉讼例子里，Claude Fable 5.1 找到一项后来被上诉推翻的裁判，Astra for Law 找到两个事实更接近的先例。这个例子只能说明具体检索差异，不能代替 200 题评测。

### 局限

54.0％ 的主要评测使用私有验证题，外部读者无法从页面复核题目和评分；对照组只是同一 Astra 加网页搜索，没有与 Harvey、CoCounsel 或其他法律产品做同条件横评。检索范围写明是美国法律，不能外推到其他法域。产品初期只给入选律所，API 页面写的是即将开放。54％ 也意味着近一半题目没有通过总体正确性检查，成品正文应把它写成增强律师研究工具，不写成能够独立提供法律判断。

### 与近期的关系

近期已连续报道 Astra 的循环架构、网络能力、正式发布、长期任务、隐藏推理和多个客户案例，模型本体高度饱和。法律版唯一应保留的增量是专用法律检索把 200 题正确率从 38.7％推到 54.0％，以及律所需要的保密控制和插件生态。不要复述 Astra 的通用能力、思维链或安全措施，也不要把它写成又一条「Astra 进入某公司」。

## Bonsai 2 27B：换上 Qwen3.8，把压缩后的成绩保留率推到 98.2％

- 推荐强度：弱。
- 档位线索：维持无牌。七月已经用银牌完整报道 27B 模型压到手机和电脑，本次正文只保留换成 Qwen3.8 27B，以及综合成绩从全精度基座的 95％提高到 98.2％；5.9GB、262K 上下文、端侧部署和 Apache 2.0 都是旧卖点。

### 核心主张

Ternary Bonsai 2 27B 把基座从上一代 Qwen3.6 27B 换成 Qwen3.8 27B，仍用 `－1、0、＋1` 三值权重与 FP16 分组缩放。它保持 5.9GB 部署体积，同时在 PrismML 的综合基准里得到 83.9 分，全精度 Qwen3.8 27B 为 85.4 分，保留率为 98.2％。

这次真正的产品增量是「同样部署点下，基座更强，压缩损失更小」。第一代官方口径为保留约 95％ 能力；第二代把它提高到 98.2％，并补上更强的推理、编程、视觉和 Agent 能力。

### 为什么值得看（钩子）

同样一个 5.9GB 的 27B 模型，两个月后换成更强基座，压缩损失从约 5％ 收到 1.8％。它说明端侧模型的升级路径可以是更换底模和改良压缩，而不必扩大设备内存。

### 关键细节／硬数字

- 模型为 1.76 个有效 bit／权重，总体积 5.9GB；相对全精度版本小九倍以上。这一部署规格与七月首代 5.9GB 三值版本相同，不算新卖点。
- PrismML 的综合分为 83.9，全精度 Qwen3.8 27B 为 85.4，Qwen3.6 27B 为 83.6；第二代对新基座的综合保留率为 98.2％，首代官方口径约为 95％。
- 分类成绩中，Agent 与工具调用为 77.57，对应全精度 Qwen3.8 的 79.74；编程为 81.58 对 82.17；数学为 96.57 对 97.06；视觉为 78.59 对 81.64。指令遵循反而是压缩版 82.66、高于全精度的 81.25，说明综合保留率不是每项都按同一比例下降。
- 官网另称 RTX 5090 最高 143 token／秒，M5 Max 为 46.8 token／秒；RTX 4090 为每 token 0.714 毫瓦时，比一个 FP16 8B 模型节能 40％。这些是厂商在不同硬件上的测量，缺少页面内的完整同条件对照，不建议挤进无牌正文。
- 权重以 Apache 2.0 开放，支持 NVIDIA CUDA 与苹果 MLX。首代七月已经具备 Apache 2.0、苹果端和本地部署，因此也不算本期增量。

### 局限

所有跑分、吞吐和能耗都来自 PrismML，页面没有第三方复现。综合 98.2％ 把多组任务归一后汇总，会掩盖视觉等单项更明显的损失；也不能从综合分推出长任务中错误不会累积。官网将 98.2％ 称作接近无损，但这是相对它选定的基准套件，不等于各种应用都只损失 1.8％。本地文件没有白皮书全文，因此无法核查量化训练流程、基准权重和测速条件。

### 与近期的关系

7 月 15 日已经以银牌写过 Bonsai 27B：Qwen3.6 27B 压到不到 2 bit，三值版 5.9GB，1-bit 手机版 3.9GB，支持视觉和工具调用，Apache 2.0 权重可下载；当时还写过量化后工具调用从 80 降到 66、视觉从 72.6 降到 59.6。第二代不能再写「27B 塞进手机」「5.9GB」「262K 上下文」或「权重开放」。唯一清楚的新对照是基座换成 Qwen3.8 27B，综合保留率由约 95％升到 98.2％，所以只能无牌短写。
