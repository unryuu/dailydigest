# Agent 是否能改进自己的目标、测试流程和运行脚手架

- 推荐强度：强
- 档位线索：三篇来自同一项目的一组基准，合起来能支撑银牌级判断：Agent 已经能够自行完成目标解释、数据选择、自测、自评、训练或脚手架修改等闭环，但改进普遍不稳定，容易只对本地反馈有效，且在代码、搜索和研究任务上仍落后成熟的人工脚手架。不够金牌，因为材料展示的是评测框架和有限条件下的实验结果，不是已经出现可持续自我进化的通用系统；原始抓取页也没有给出训练算力、总运行成本或完整分项成绩。
- 涉及文章：[Aspire：Can Models Self-Evolve from Vague Goals？](https://huggingface.co/papers/2608.31111) · Hugging Face Papers／ByteDance Seed · 2026-08-31；[S³Gym：Can LLMs Turn Self-Testing and Self-Judging into Self-Improvement？](https://huggingface.co/papers/2608.31100) · Hugging Face Papers／ByteDance Seed · 2026-08-31；[HarnessDev：Can LLMs Create and Evolve Their Own Agent Harness？](https://huggingface.co/papers/2609.01437) · Hugging Face Papers／ByteDance Seed · 2026-09-01

## 核心主张

这组三篇把“自我改进”拆成三个层次：Aspire 要 Agent 从模糊能力目标出发，自行把目标变成可训练、可验证的问题；S³Gym 要它在环境里自行测试、判断经验，再把经验变成后续策略；HarnessDev 则要求它从最小种子搭建并反复修改模型外部的运行脚手架。三个基准都说明，当前 Agent 已能完成形式上的迭代闭环，但闭环不等于可靠进步：它们会选错数据、相信过窄的自评、把经验压缩掉关键状态，或者在继续训练时抹掉此前收益。最硬的结论不是“Agent 会自我进化了”，而是“目标解释、反馈转化和跨任务迁移，才是自我改进真正的瓶颈”。

## 为什么值得看（钩子）

主流叙事常把更多试错和更多训练等同于进步，这组三篇直接反驳了这一点：Agent 甚至可以完整执行自我改进流程，却越改越差。它们还把评测对象从最终答案推进到目标、记忆、训练和运行基础设施本身，适合合并成一条有明确反直觉结论的论文报道。

## 关键细节 / 引述

- Aspire 只提供自然语言能力目标，隐藏下游评测任务；Agent 必须自行解释目标、选择数据和更新方法、构造训练与验证信号，并决定何时评估。外部最终监督来自六个目标、共 520 道专家编写的隐藏题，目的是检验自建目标和自评是否真的迁移，而不是只看 Agent 自己宣布成功。
- Aspire 同时允许修改模型权重和 Agent harness。实验中 Agent 经常能够完成训练和脚手架编辑循环，但权重层面的收益“稀疏且不稳定”；最强的自演化脚手架仍低于人工工程化的 Qwen-Agent 参考方案。失败原因包括训练数据与真实目标不匹配、过度相信狭窄自评、局部收益不能迁移到隐藏评测，以及继续搜索和训练反而擦除早期提升。
- S³Gym 把闭环明确拆成 Self-Testing、Self-Judging 和 Self-Improvement，在七个文字游戏中允许自由探索，但用严格的留出评测和可执行环境验证器判定结果。这意味着反馈并非纯靠模型自说自话；环境能验证行为是否成功，同时开发经验与最终评测被分开，原文没有显示直接把隐藏题暴露给 Agent 的评测泄漏。
- S³Gym 比较三条经验利用路径：直接把历史放入上下文、把经验压缩成带分数的摘要记忆、以及参数训练。摘要只在经验能够提炼成可复用策略规则时有效；需要精确、依赖当前状态的信息时，摘要往往不如原始历史。参数训练在部分任务上提升明显，但在另一些任务上出现不稳定改进和严重负迁移，说明识别成功动作不等于学会可执行、可迁移的策略。
- HarnessDev 的 Creation 阶段让 Agent 从最小种子和少量案例搭建完整执行系统；Evolution 阶段再根据下游执行反馈反复修改自建 harness。评测同时看隐藏基准上的任务成功率和执行 token 成本，覆盖六个创建模型、四个领域、五个下游基准，共 2207 个独立实例；隐藏任务不参与开发，降低了直接针对测试集调参的风险。
- HarnessDev 中，自建脚手架在代码、搜索和研究任务上明显落后成熟的人工工程方案，在写作和机器学习实验上则能追平或超过所选参考方案，但执行成本差异很大。迭代修改有时带来提升，却不稳定、只部分迁移到留出任务；固定运行模型的实验还显示，同一脚手架的收益高度依赖实际执行它的模型，跨模型迁移有限。
- 三份本地抓取都没有披露训练所需 GPU、训练 token、总推理调用次数、墙钟时间或金钱成本，因此无法判断这些自我改进相对人工开发是否具有算力或成本优势。HarnessDev 只说明把执行 token 成本纳入评测，没有给出摘要页上的具体数值；报道时不应补写“更省成本”或“可无限自我迭代”。

## 与近期的关系

三篇属于同一团队、同一项目页在相邻日期集中发布，主题和结论高度互补，适合合并为一条，不宜拆成三条造成版面内重复。与近期常见的“Agent 自我改进”“自动搭建 Agent”“从经验学习”叙事存在概念重复风险，但这组的新角度是用隐藏评测揭示自评错位、负迁移和人工脚手架仍占优；标题和正文应突出“跑通闭环仍不等于进步”，避免泛写成又一轮 Agent 自我进化。
