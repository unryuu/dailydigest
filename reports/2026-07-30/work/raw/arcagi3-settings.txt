TITLE: How enabling two settings tripled our scores on the ARC-AGI-3 benchmark
AUTHOR: Ilan Bigio, Ted Sanders
DATE: 2026-07-29
抓取方式: 浏览器面板（脚本抓取 403，2026-07-31 02:42 补抓）
============================================================

核心：同一个模型，只改两个 API 设置，分数变三倍、输出 token 少六倍。
这条的价值不在分数，在于**评测测的从来不只是模型本身**。

关键数字（都来自官方原文）：
- 官方 harness 下，GPT-5.6 Sol 在 ARC-AGI-3 公开集得 13.3%。
- 打开「保留推理」+「压缩」两个设置后，得 38.3%。约三倍，输出 token 少 6 倍。
- 最初看到的更低分是 7.8%（GPT-5.5 只有 0.4%，几乎玩不了）。
- 计分口径是 RHAE（相对人类行动效率），据官方对局日志估算，人类测试者平均约 48%。
- 单看某个游戏的排行榜：没有任何前沿模型能通过第一关；用他们自己的 harness，Sol 六关全过。

问题出在哪（两条，都是 harness 的设定而非模型能力）：
1. 每次游戏动作之后，模型的私有推理**全部被丢弃**。等于每走一步都要从头重新理解这个游戏，
   看得见过去的动作记录和简短备注，但看不见导出这些动作的计划、洞察和思路。
2. harness 用滚动截断：上下文超过 17.5 万字符就丢最旧的消息。于是不但记不住自己想过什么，
   连做过什么也在逐渐失忆。

改法：
- 用 Responses API 实现 harness，对 GPT-5.6 传入上一个 response ID 就能自动在工具调用和
  多轮之间保留推理。效果：每步思考时间变短（不用每回合重新解读游戏），且更善于随时间学习、
  采取连贯策略。
- 用 compaction（压缩）替掉滚动截断，长局中更能保住已经学到的东西，分更高且输出 token 更少。

官方给 API 开发者的建议（可作正文一句）：用 Responses API 而不是旧的 Chat Completions；
保留推理；开压缩。比较模型时也建议采用这套设置的评测，因为它更贴近 ChatGPT 和 Codex 里
的真实用法。

一句自评（适合当收尾）：这不是他们第一次先被公开基准上的低分吓一跳，后来才发现评测运行方
用的是会丢掉推理消息的通用 harness。

★ 与赔率盒子的互文：赔率池里有「2026 年内会有模型在 ARC-AGI-3 上拿到超过人类的分数吗」
（25.8%，Zvi 开的盘）。人类基线约 48%，这次调设置后是 38.3%——两条并排看很有意思。
