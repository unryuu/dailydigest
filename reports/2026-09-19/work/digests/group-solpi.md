## 核心主张

SoL-Pi 让 Agent 在许多可执行任务环境里提出、实现和验证外壳代码改进，目标是减少反复传上下文、工具输出和额外模型调用的开销。研究对象是 Pi 周围的工具执行、上下文管理、观察结果处理与委派阅读机制，不是修改基础模型权重，也没有展示底层模型的递归训练。

152 个初始方向最后留下四种机制；在 51 任务 EdgeBench 上，与 Pi 相比，记录到的 token 流量减少 44.7％—49.0％，按官方 API 价格折算的费用约少三分之一，同时只保留 Pi 约 94％ 的平均得分。因此应写成「小幅得分损失换取较大开销下降」，不能写成「成功率完全相同」或「能力毫无下降」。

## 为什么值得看（钩子）

新增点是让研究 Agent 自动找到并验证具体省钱机制，而不只是发现换一种外壳账单不同。官网也承认，单机制允许的小幅能力退步会在组合时累积；「省下的钱继续加速下一轮自我改进」仍是愿景，尚未证明复利效果。

## 关键细节 / 引述

- **搜索方法。** 先从已有轨迹估计可省的工作，再将想法分成独立研究支线。各支线经过轨迹生成、多个分析者汇总证据、机制提案、一个 Agent 实现、另一个 Agent 审查、开发集筛选，最后冻结候选及验收规则，在隔离测试集验证。官网称测试轨迹和结果不回流给研究循环，测试失败只淘汰，不用于修补同一候选。开发环境共 535 个，其中 495 个由 GitHub issue／PR 配对构建，40 个围绕可执行验证器合成。
- **动作合并。** Action Fusion 把编辑文件和紧接着的测试、构建或运行命令合成一次工具调用，外壳本地顺序执行再统一返回，省掉中间一次模型决策。它不是把所有操作都并行，也不是取消验证。
- **上下文与输出。** Online Context Compact 在子任务完成时重新考虑压缩，只有预计后续收益能抵消重写成本才执行。ObservationPack 把大文件或工具输出存到本地，在上下文里留下稳定引用和短摘录，需要时取回原文分页，避免每轮反复携带全文。
- **委派阅读。** Evidence-Preserving Reducer 先让便宜 Agent 读长日志，输出紧凑诊断；外壳逐条核对引用是否存在于归档日志，再交给前沿模型。这里核的是引用证据，不能扩写成摘要所有判断都已经正确。
- **结果与口径。** EdgeBench 用 GPT-5.6 Sol、Opus 5，两者均采用本次评估最高的 xhigh 推理档。相对 Pi，记录 token 流量少 44.7％—49.0％，API 等价费用约少三分之一，平均得分保留约 94％；「94％」是对 Pi 平均得分的比例，不是 94％ 任务成功率。相对各模型原生外壳，token 少 35％—64％，按标价折算费用少 50％—54％，是另一组基线，不能和前一组混写。官网提到另测了 63 个 CPU 任务的 Terminal-Bench 4，但本地正文没有图柱上的具体数值，不据此补数字。
- **有限的群体实验。** 单个 Sol 协调 20 个 Luna 工作者，比较工作者使用 Pi 或 SoL-Pi；同一内核优化任务每种配置各跑一次两小时、从同一冻结起点开始。SoL-Pi 群体结果为 1127 个模拟机器周期、API 等价费用 60.11 美元；Pi 群体为 1366 个周期、82.12 美元。单 Sol 为 1333 个周期、39.20 美元，仍最便宜。三次试验是三个配置各一次，不能写成每组重复三次或广泛证实多 Agent 更划算。

## 试验限制

这是一套有人参与设定先验、筛掉低价值方向并整理最终代码的混合研究流程。作者称进入单条研究循环后研究与验证无需人类干预；候选通过后人再理解机制并重构为可维护实现，不能省略成从头到尾无人研发。

四种机制的验收分别约束能力退步幅度，组合仍有约 6％ 的相对平均得分损失。论文页「表现可比」的概括应以官网这个更具体的限制为准。token 流量不是输出长度，也不是训练 token 数；API 等价费用来自官方价格折算，不宜写成所有用户实际账单或订阅费用。

作者只说观察到同一研究方向迭代约五至十次后容易陷入局部优化，扩大起始方向有助于找到少数有效机制；这不是证明普遍的研究扩展定律。官网明确把下一轮以 SoL-Pi 为起点、让效率提升反过来资助更多搜索，列为尚未展示复利效应的长期愿景。
