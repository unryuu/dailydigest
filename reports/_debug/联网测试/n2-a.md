## 一、enklypesalt.com《Context Collapse, Part 3 — AI Worming through Word》

链接：https://enklypesalt.com/posts/context-collapse-part3-ai-worming-through-word/
状态：**成功**

**核心主张**：作者 Håkon Måløy（2026-07-28 发布）宣称这是首次记录到的、能在主流办公软件里自我复制传播的提示词注入攻击——文档里的隐藏指令让 Copilot 篡改新生成的文档，并把攻击指令本身复制进去，形成「文档蠕虫」。

**关键细节**：
- 载体是白底白字的隐藏文本，内容为 JSON 格式指令；Copilot 处理前会剥掉格式，于是人看不见、模型读得到。
- 两阶段：第一阶段，恶意文档被当作附件参与起草，Copilot 把嵌入指令当成任务指示执行（示例：把财务数字改成一半），并把整段 XPIA 隐写进产出文档；第二阶段，被污染的产出文档成为新的攻击源，同事拿它当 Q2 报告的素材时再次触发，原始恶意文档已不需要在场。
- 根因是信任边界破裂：Copilot 必须读外部文档才能判断相关性，却把它当权威指令而非不可信信息源。作者的说法是，模型要先处理攻击者控制的 token 才能判断安全性，等判断出来时这些 token 已经在影响计算了。
- 「LLMs all the way down」：在前面加一个检测用 LLM 只是把漏洞挪个位置，弱检测器识别不出强模型能理解的恶意表述。
- 披露时间线：2026-03-06 报 MSRC → 04-03 首次缓解（Edit with Copilot）→ 06-08 升 GPT-5.5 → 07-14 二次缓解（GPT-5.6）→ 07-28 在全部缓解生效的情况下仍复现成功。文中明确写：发稿时对这一整类漏洞没有可靠缓解方案。
- 建议：把外部来源文档一律视为不可信；分发前人工复核 Copilot 编辑过的文件；系统层面保留素材与模型编辑的溯源元数据，并在架构上把「系统意图」和「信息处理」独立开——这属于要做研究，不是打补丁。
- 危害放大点：一旦进入内部文档，攻击就获得「机构合法性」，经 SharePoint／Teams 扩散到合作方，事后极难追溯源头。
