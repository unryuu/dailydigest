# Qwen 3.8 27B 本地实测：17GB 模型能做视觉与编程，但默认推理强度严重过量

- 推荐强度: 中
- 档位线索: 有银牌线索，但不宜只按“又一个模型能在笔记本运行”定牌。硬点是独立本地实测给出了默认 `xhigh` 推理的时间与 token 代价，并验证可通过降低或关闭推理改善；扣分是近期已连续报道本地开放权重 Agent 与 Qwen 3.8，且测试机器属于高端设备。若当日大盘拥挤，可降无牌。
- 涉及文章: [Qwen 3.8 27B is excellent, but it defaults to wildly overthinking things](https://simonwillison.net/2026/Aug/16/qwen-38-27b/) · Simon Willison’s Weblog · 2026-08-16

## 核心主张

Qwen 3.8 27B 是 Apache 2.0 许可、支持视觉的 270 亿参数开放权重模型。Simon Willison 在 128GB M5 Max MacBook Pro 和 NVIDIA DGX Spark 上实测 17GB 的 `Q4_K_M` 量化版，确认它能生成质量较高的 SVG、做图像框选、编写工具并驱动编程 Agent；但默认 `xhigh` 推理强度会把简单任务也扩张成长时间推理，明显拖慢本地使用。推理强度可以调到 `medium`、`low`，也可关闭；低推理更适合起步，但完全关闭有时会损失一次做对复杂工具的能力。

## 为什么值得看（钩子）

反直觉之处不是小模型做不到，而是它“太想做好”：270 亿参数、17GB 文件已经覆盖长上下文、视觉、工具调用和编程，真正妨碍日用的反而是默认推理预算与内存带宽造成的速度。

## 关键细节 / 引述

- 作者在 128GB M5 Max MacBook Pro 与 NVIDIA DGX Spark 上使用 LM Studio 运行 17GB 的 `Q4_K_M` 量化版，也在 Spark 上直接试过 `llama-server`。这是高端本地硬件实测，不能泛化成普通低配笔记本都能顺畅运行；原文也没有给最低内存需求或整机成本。
- 官方支持 `reasoning_effort`：`xhigh` 为默认档，另有 `medium` 和 `low`，用于调节推理深度、速度与成本。作者明确建议忽略默认值，先用 `low`，甚至先关闭推理。
- LM Studio 默认上下文为 8192 token 时，模型连普通问题都会把窗口全部用于思考。作者改用模型完整的 262144 token 上下文后，才避开这一限制，但这不等于过度推理本身消失。
- “鹈鹕骑自行车”SVG 在默认 `xhigh` 下耗时 21 分钟，使用 22276 个推理 token，最后输出 3223 个 token；关闭推理后，同一提示输出 3715 个 token，只花 137 秒。前者是作者在本地模型中见过的最佳鹈鹕 SVG，但他判断完全不值得等待 21 分钟。
- 面对一句“画一个圆的 SVG”，模型先规划同心辅助圆、刻度、渐变、动画和无障碍处理，几分钟后交出一个漂亮的动画圆，却偏离了用户只要一个圆的要求。这是默认推理把简单任务自行扩写的最直接例子。
- 过度思考并非纯负面：模型按提示生成图片框选可视化网页时，开启推理后一次做出了可用完整界面，还主动增加未要求的演示场景；关闭推理的版本几乎可用，却把框画错了位置。原文因此只支持“默认值过高”，不支持“推理应一律关闭”。
- 视觉测试中，模型按 0—1000 坐标返回两只鹈鹕的边界框，作者渲染后认为位置高度吻合。编程测试中，它通过 Pi 读取 Datasette 多个文件解释认证机制，又编写并测试了把 Pi 会话 JSONL 转成 Markdown 的 Python 脚本。
- LM Studio 实测速度约为每秒 15—30 token。作者引用 Artificial Analysis 对比：OpenAI 5.6 Sol 为每秒 74 token，5.6 Luna 为每秒 184 token。Spark 上启用模型的 Multi-Token Prediction 后，其对比基准比 LM Studio 默认 GGUF 快约 72％；这只是特定机器与服务配置的结果，不是通用速度保证。
- 作者认为日用的主要障碍仍是性能：27B 是稠密模型，对内存带宽要求高；M5 Mac 和 DGX Spark 在这方面都不算顶级。Qwen 官方自报跑分显示它超过 Qwen 3.6 27B 与闭源 Qwen 3.7-Plus，但文章没有独立基准验证这些排名。
