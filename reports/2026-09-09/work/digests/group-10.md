# Mercury 2.5 把扩散语言模型推入生产环境

- 推荐强度：强
- 档位线索：银牌候选；不仅有厂商性能数字，还有搜索、语音和编码产品的生产使用结果。
- 涉及文章：[Introducing Mercury 2.5](https://www.inceptionlabs.ai/blog/introducing-mercury-2-5) · Inception Labs · 2026-09-08

## 核心主张

Mercury 2.5 延续扩散式语言模型一次处理多个 token 的路线，把重点从演示速度推进到低延迟生产任务。它已经用于搜索流水线、电话 Agent 和编码工具中的上下文压缩、路由与工具检索。

## 为什么值得看（钩子）

这次真正值得写的不是又一个模型榜单，而是扩散语言模型开始在延迟敏感的真实产品中承担重复调用。

## 关键细节 / 引述

- 厂商称推理速度为每秒 1107 token，上下文长度 26 万 token。
- 正常价格为每百万输入 token 0.20 美元、输出 token 0.75 美元；首发期打八折之外再降至原价的 20％。
- OpenCall 的生产负载中，模型响应延迟中位数接近 170 毫秒，P99 从数分钟降到 1 秒。
- Augment Code 用它做上下文压缩、模型路由和 MCP 工具搜索；压缩延迟从约 150 秒降至 27 秒，成本下降 90％。
- 模型支持可调推理、并行工具调用和符合 schema 的 JSON，并通过 Inception API、Baseten 和 OpenRouter 提供。
