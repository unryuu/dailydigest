# ChatGPT Images 2.5 的产品工作流变化

- 推荐强度：强
- 档位线索：银牌偏强。每周超过 30 亿张、生成延迟最多降低 50％，再加上 Sketch、图上评论、模板和可分享提示词，足以支撑一条完整产品更新；但能力改善与速度数字主要来自 OpenAI 自述，没有独立横评，不宜升金。
- 涉及文章：[Introducing ChatGPT Images 2.5](https://openai.com/index/introducing-chatgpt-images-2-5/) · OpenAI · 2026-09-08
- 涉及文章：[Introducing ChatGPT Images 2.5](https://simonwillison.net/2026/Sep/8/introducing-chatgpt-images-25) · Simon Willison’s Weblog · 2026-09-08

## 核心主张

Images 2.5 的变化不只是一轮画质升级，而是把「草图表达意图—参考图生成—图上指定修改—多轮迭代—复用提示词」串成 ChatGPT 内的创作工作流。模型侧重点是参考主体保真、只修改被点名的元素，以及多轮编辑时保留此前改动和画质；OpenAI 同时把 API 分成偏速度和通用场景的 Flare，以及偏精细编辑控制的 Sunburst。OpenAI 称 ChatGPT Images 与 API 中的 GPT‑Image 模型每周合计生成超过 30 亿张图，但公告没有拆分 ChatGPT 与 API 各自用量。

## 为什么值得看（钩子）

最值得看的不是「又一个生图模型」，而是生成器开始吸收画布工具的交互：用户可以直接画草图、在图上留修改意见，并让后续编辑继承前面的成果。每周超过 30 亿张说明它已是大规模产品能力，不过公告仍以厂商展示与客户引语为主，缺少同条件外部测试。

## 关键细节 / 引述

- OpenAI 称，ChatGPT Images 与 API 中 GPT‑Image 模型的合计使用量超过每周 30 亿张图片；这是生成图片数，不是用户数。
- 与 Images 2.0 相比，Images 2.5 的生成延迟最多降低 50％。官方还称其自然光照、纹理、参考图主体保留、复杂视觉指令理解、透明背景和多轮编辑一致性都有改善；这些均是官方能力表述，没有随文给出完整基准。
- ChatGPT 新增 Sketch：输入 `@Sketch` 后可直接画房间布局、服装轮廓等草图，连同风格描述交给模型生成。另有 Poster、Merch 等模板、直接在图片上评论以聚焦局部编辑，以及分享图片时附带提示词供别人替换成自己的图片和细节。
- 产品内的精细编辑目标是只改被指定的产品、背景或文案，同时保持主体、构图和品牌处理不变；多轮会话中，较早的修改应尽量保留，后续编辑建立在已有结果上，而不是重做整张资产。
- Images 2.5 于 9 月 8 日开始向 ChatGPT、ChatGPT Work 和 Codex 的所有档位推出，覆盖桌面端、移动端与网页端。公告表述为「rolling out today」，不等于所有账号当时已经同时可见。
- API 同时提供 `gpt-image-2.5-flare` 与 `gpt-image-2.5-sunburst`。Flare 是官方建议的大多数应用默认选项，官方称其比 GPT‑Image‑2 画质更高且延迟低 50％，适合社交内容、产品功能、视觉搜索、快速原型和大批量生成；Sunburst 生成时间更长，换取跨编辑步骤更精确的控制，面向成品广告与精修商品图等高要求流程。公告只链接价格页，正文没有给出可引用的价格数字。
- Simon Willison 将 Sunburst 理解为两者中编辑精度更强的选项，并更新自己的 `openai_image.py` 工具，使其可向新 API 传入一张或多张参考图；他用 Sunburst 演示了在原图中添加一只研究图表的浣熊科学家。这是可调用性与工作流示例，不是对两款模型的独立对比评测。
- Manus 称其内部评估中 Flare 达到 GPT‑Image‑2 的 2 至 4 倍速度，Adobe 则宣布新模型进入 Firefly。前者是早期客户自己的口径，不能与 OpenAI 的「延迟低 50％」混成同一基准。
- OpenAI 称继续使用提示词与图片检查、C2PA 元数据和不可见水印；公告未给出这些措施对具体滥用类型的新增效果数字。

## 与近期的关系

直接重复风险低：现有历史日报里，GPT‑Image‑2 只在 7 月 15 日作为 Sol 自动生成精灵图的底层工具出现，7 月 25 日又作为视觉作答基准中的参评模型出现，均未报道 Images 2.5 或这套产品工作流。题材层面的重复风险中等，成稿不要泛写画质变好，应落在 Sketch、图上评论、多轮局部编辑和 Flare／Sunburst 分工这组新增变化；也不要把官方演示写成已经由外部评测证实。
