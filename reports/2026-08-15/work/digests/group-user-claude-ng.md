## 核心主张

Claude Code 文章认为，Agent 编程的成本不只取决于模型价格，也取决于有多少内容进入上下文、这些内容在多少轮里被反复发送，以及同时运行多少个上下文；因此，切任务时清空会话、控制命令输出、提前选定模型和推理强度，都是实际的成本管理。Andrew Ng 则把当下开发者最需要的能力归为构建和部署 AI 应用、软件工程基础、使用编程 Agent、塑造要做的产品四类；他的反常识点是，Agent 越会写代码，软件工程基础和决定「该做什么」的产品判断反而越重要。

## 为什么值得看（钩子）

Claude 一篇不是泛泛的「提示词技巧」，而是解释了同一个任务为什么会因会话组织方式不同而产生不同 token 成本。Andrew Ng 一篇给出了技能变化的清晰方向，但更像详细地图发布前的纲要，适合简讯提醒，不宜包装成完整研究结论。

## 关键细节 / 引述

### Claude Code 会话

- 模型先在 prefill 阶段读取系统提示、`CLAUDE.md`、用户消息、文件和命令输出，再在 decode 阶段逐 token 生成思考、工具调用与可见文本。文章称输出 token 单价约为输入 token 的五倍。
- 提示词缓存读取价格是普通输入的 0.1 倍，写入缓存最高可达普通输入的两倍；但切换模型、推理强度或 Fast mode 会改变缓存键，让后面的长会话重新以全价预填充。因此，文章建议在新会话开始时，或执行 `/clear` 后，再切模型和推理强度。
- 缓存在订阅环境下一小时过期，API key 默认五分钟过期；`ENABLE_PROMPT_CACHING_1H=1` 可将 API 缓存设为一小时。文章建议离开电脑前先 `/compact`，因为旧会话仍在缓存时生成摘要更便宜，而恢复很久以前的会话通常需要重新预填充。
- 文件和命令输出一旦进入对话，之后每一轮都会随完整上下文再次发送。超过三万字符的命令输出会被写入文件，只把预览和路径放进对话；反而是低于阈值、但打印数百行的测试输出，会长期占据上下文。
- 官方给出的操作优先级包括：不同任务之间 `/clear`；会话开始前设好模型与 `/effort`；用 `@` 直接附文件，省掉一次 Read 或搜索；为高噪声命令加安静参数，或交给独立 subagent；新会话先用 `/context` 检查自动加载内容；离开前 `/compact`。
- 文章明确提醒，subagent 适合日志分析等会产生大量无须保留输出的任务；小任务可能因为重新读取文件和单独运行多轮，反而只有额外开销。

### Andrew Ng 技能地图

- 团队称其依据包括超过一万条招聘信息、数十次对 AI 专家、招聘经理和招聘人员的结构化访谈、问卷及其他在线数据；但本篇没有给出招聘信息的地区、时间、岗位构成、统计方法或各技能权重。
- 四类技能是：构建和部署 AI 应用、软件工程基础、使用编程 Agent、塑造构建方向。Andrew Ng 强调这不是「AI 工程师」这一职位的专属技能，而会像云能力一样，成为全栈、数据、运维和机器学习等开发者的共同基础。
- 他把 AI 应用区别于传统软件的核心归为输出不可预测，因此开发者不仅要懂 LLM、上下文工程、RAG、Agent 工作流和机器学习，还要会用统计方法、评估与错误分析循环，让系统行为变得更可测、更可控。
- 他反对把 Agent 编程理解成不再需要软件工程基础：不了解成本、扩展性、可靠性、安全和隐私等权衡的人，也不知道该给 Agent 什么上下文，Agent 很可能替他做出糟糕选择。
- 「使用编程 Agent」被拆成管理上下文、权衡规划与执行、提供验证器或评估来闭环、判断何时需要清晰规格、编排多个 Agent，以及防止 Agent 破坏生产数据库等能力。
- 「塑造构建方向」指工作重心从照着像素级设计实现，转向决定规格里应该有什么；这要求产品感、商业背景、客户目标与项目推进判断。Andrew Ng 同时说明，详细技能地图会在之后的信件中继续展开并更新，本篇结尾还征集一份约五至七分钟的社区问卷。
