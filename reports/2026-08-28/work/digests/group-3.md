# Claude Code 自动模式放过攻击，却拦住清理

- 推荐强度: 强
- 档位线索: 够银牌。它不是泛泛讨论提示注入，而是给出了安全机制反向扩大危害的具体失败链；但当前材料是 Simon Willison 转述 Johann Rehberger 的研究与结论，80％成功率也属于研究者声称，不宜仅凭这篇二手材料升金。
- 涉及文章: [Breaking Claude Code Opus 5 Auto Mode](https://simonwillison.net/2026/Aug/27/breaking-claude-code-opus-5-auto-mode/) · Simon Willison’s Weblog · 2026-08-27

## 核心主张
Anthropic 最近把 Claude Code 的自动模式设为默认，并把它当作抵御提示注入的重要防线，但 Johann Rehberger 找到了一条据称约有 80％成功率的绕过路径。更反直觉的是，自动模式不只放行了恶意进程的创建：在 Claude 察觉入侵并尝试终止进程时，它有时还拒绝执行清理命令，使安全机制本身成为故障链的一部分。Simon Willison 据此认同 Rehberger 的结论：面对对抗性攻击风险，无人值守的编码 Agent 仍必须运行在受限制的沙箱中。

## 为什么值得看（钩子）
最有新闻价值的不是“Agent 仍会中提示注入”，而是权限分类器在同一条攻击链上先放过危险操作、再阻止补救操作：安全控制从失效变成了主动妨碍恢复。

## 关键细节 / 引述
- Rehberger 的攻击会诱导 Claude Code 下载并解压一个 ZIP 文件，再执行导入 `base64` 的代码；此时 Python 会优先导入压缩包解出的本地 `struct.py`，从而执行其中的恶意代码。
- Rehberger 声称这条针对自动模式的攻击约有 80％的成功率；原文将这一数字明确归于他的测试结论，而非 Anthropic 或 Simon Willison 的独立复现。
- 在部分运行中，Claude 已发现系统遭到入侵并尝试终止恶意进程，但自动模式拒绝了用于清理的命令。
- Simon Willison 对该失败模式的概括是：分类器允许创建恶意进程，却阻止了旨在终止它的命令。
- Willison 认同 Rehberger 的防护建议：无人值守的编码 Agent 应放在容器、虚拟机或操作系统沙箱内运行，同时限制网络出口并持续监控。
- 运行环境不应向 Agent 暴露主目录、SSH 密钥和云凭据等敏感资源。
