# DeepSeek V4.1 的 Agent 成绩可能主要取决于外壳适配

## 核心主张

Teortaxes 认为，DeepSeek V4.1 对 Agent 外壳和提示配置尤其敏感：极简 harness 已能运行，但针对具体场景优化 `AGENTS.md` 可能带来巨大增益。因此 Agent 排行榜实际比较的不是裸模型，而是 adapter、harness 与模型的组合；换一层适配器，就可能大幅改写同一模型的成绩。

这个判断目前主要是作者观点，不是已核实的对照实验。结构化候选记录提到默认 Agent 为 3／70、接入 Codex 后为 11／70，但原始抓取正文没有出现这两个数字，也没有 Terminal-Bench Science 的提交链接、配置或截图，无法判断两次运行是否只改变 Agent 外壳。

## 为什么值得看（钩子）

如果对照成立，同一模型换一个外壳就能从 3 题做到 11 题，所谓「模型排行榜」会更像整套工程栈排行榜。不过目前恰恰缺少足以支撑这个反差的原始证据。

## 关键细节 / 引述

- Teortaxes 原帖的明确表述是：他对 benchmark 衡量峰值能力「相当宿命」，因为即使只是 `AGENTS.md`，也会对打磨不足的模型产生巨大影响；他特别称 V4.1 很「brittle」，极简 harness 下可以表现不错，但为场景优化提示后可能出现巨大增益。
- 原帖引用 Benjamin Marie 的判断：评测的不是单纯的 harness 与模型二元组，而是 adapter、harness、model 三元组；adapter 又是最容易被专门调榜的一层。他举的抽象例子是，DeepSWE 的 Pi 若只通过基础 Pi-to-Pier adapter 接入，成绩会差很多。
- 当天 `x_candidates.json` 的结构化记录称，Teortaxes 援引 Terminal-Bench Science 的不同运行方式，V4.1 在默认 Agent 中做对 3／70 项，接入 Codex 后为 11／70 项，并称其物理科学任务接近 Opus 5 配合 Claude Code。该记录自身也明确标注：数字来自个人帖子和被引用的排行榜截图，必须回到排行榜与对应提交核实。
- 已分配的原始抓取文本只保存到 Teortaxes 的总判断和 Benjamin Marie 的引用，没有出现 3／70、11／70、物理科学分项、排行榜名称、提交者、日期、模型版本、运行预算或复现设置。因此这些数字目前不能当作已读到的一手事实。
- 现有材料也没有说明所谓「接入 Codex」究竟只替换 harness／adapter，还是同时改变系统提示、`AGENTS.md`、工具、上下文管理、采样参数、运行次数或算力预算。即使两条排行榜数字本身真实，也不能据此把 3 到 11 的全部增益归因给 `AGENTS.md`。

## 与近期的关系

9 月 10 日已经把 DeepSeek V4.1 Flash 开放权重定为银牌，并写过 MIT、5520 亿主干参数、一百万 token 上下文、输入与输出激活参数量，以及 KV 缓存压到前代四分之一。`STATUS.md` 也明确规定后续只收独立实测、部署成本和推理架构等增量，不能重复上述发布信息。
