# Activation Oracles 微调后出现概念盲点

- 推荐强度: 强
- 档位线索: 有金牌潜力。结论反直觉，而且直接动摇了把 Activation Oracle 当作中性读出器的可靠性假设；实验数字与机制定位都较完整。
- 涉及文章: [When Activation Oracles Learn Not to Read: Concept-Specific Blind Spots in Fine-Tuned Oracles](https://huggingface.co/papers/2607.23379) · Hugging Face Papers · 2026 年 7 月 25 日

## 核心主张
Activation Oracle 并不是对模型内部表征的中性读取接口，它的回答也会被训练数据、目标函数和学到的汇报行为塑造。研究在 Taboo Word Guessing 场景中发现：拿某个刻意隐藏概念的主体模型来微调 Oracle，并不会让它更擅长读取该主体，反而会让它选择性地读不出训练期间持续出现的那个概念，同时仍能正常读取其他概念。更关键的是，概念信息并未消失，故障发生在 Oracle 把内部表征映射成输出词的读出路径上。

## 为什么值得看（钩子）
这项工作把「专门训练一个审计器，它就会更懂被审计模型」这个直觉倒了过来：专项微调可能训练出一个对目标概念特别自信、却特别看不见的反读器。

## 关键细节 / 引述
- 论文把这种现象命名为「concept-specific anti-reading」：在测试的五个概念上，针对隐藏概念 c 的主体模型微调后，Oracle 都会选择性降低对 c 的恢复能力，但读取其他概念仍然正常。
- 对合作型主体模型，隐藏概念的精确恢复率从基础 Oracle 的 94％降至针对该主体训练后的 35％；在另一个隐藏概念上训练的 Oracle 仍可达到 71％。
- 失败不能简单归因于概念已从主体模型或 Oracle 的表征中消失：基础 Oracle 仍能恢复该概念，而且该概念在微调后 Oracle 内部依然可以被线性解码。
- Logit Lens 分析显示，目标概念在 Oracle 的中间层仍然存在；消融 Oracle 的中后层后，概念恢复能力反而会回来，说明问题位于后续读出路径。
- 出错的 Oracle 通常表现得很自信，而不是犹豫或不确定。这意味着仅看回答置信感，难以识别这种概念盲点。
- 论文据此区分了三件可以彼此脱钩的事：行为层面的信息泄露、表征层面的可解码性，以及 Activation Oracle 能否把信息说出来。
