# SlopCodeBench：贴近真实迭代流程，量化「AI 改代码越改越烂」

- 日期：2026-07-28
- 来源：https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/benchmarking-opus-5-on-slop-code-bench.md（主文）
- 主题：四、评测与实验设计

## 这是什么

更贴近真实开发流程。Opus 5 通过率 24%，前代最高 17%，但 Opus 5 的代码量翻了三倍，冗余程度是真人代码的 11 倍。

## 可以怎么用

- 评测 coding agent 不能只看「测试通过率」这一个数字，还要量化改动量/冗余度（比如代码量倍数、与真人代码的冗余度对比），通过率涨了但代码质量可能在同步变差。
- 「贴近真实迭代开发流程」而非一次性给题的评测设计，更能暴露「越改越烂」这类只有在多轮修改中才会累积的问题——自查自己 agent 产出时，也该看多轮迭代后的代码量/复杂度变化趋势，而不只看单次输出。
- 可以把「代码冗余度相对真人基线的倍数」当成一个日常自查指标，定期抽查 agent 改过的代码是否在无谓膨胀。
