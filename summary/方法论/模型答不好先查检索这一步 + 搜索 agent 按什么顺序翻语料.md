# 模型答不好先查检索这一步 + 搜索 agent 按什么顺序翻语料

- 日期：2026-07-27 / 2026-07-29
- 来源：https://www.deeplearning.ai/the-batch/web-retrieval-flusters-llms（近四成错误是压根没搜到该看的页）；https://huggingface.co/papers/2607.24223（先按相关性给语料排名让 grep 顺序扫、命中片段二次重排，78%→84%）
- 主题：八、效率工具与本地模型

## 这是什么

**2026-07-27**：用六种语言的 BBC 新闻出题，近四成错误是，压根没搜到该看的页面。与其堆参数，不如先把检索做好。

**2026-07-29**：先用相关性给整个语料库排名，让 grep 按名次往下扫，命中的片段再重排一遍。搜索基准上准确率从 78% 提到 84%，工具调用还更少。

## 可以怎么用

- 遇到模型答不好一个问题，先怀疑「它到底有没有搜到该看的那页」，而不是急着换更贵的模型或加参数——研究显示近四成错误压根出在检索没找对页面这一步。
- 排障顺序可以固定成：先查检索命中率，再查模型理解/推理能力，最后才考虑换模型。
- 自建检索/搜索 agent 时，可以借鉴「先整体排名、再按名次顺序扫、命中片段二次重排」的两段式设计，比单纯堆一次检索排序更省工具调用、准确率也更高。
- 这两条材料合起来提醒一件事：很多「AI 效果不好」的问题，根子在检索管道而不是模型本身，排查顺序该反过来——先修检索，再谈模型。
