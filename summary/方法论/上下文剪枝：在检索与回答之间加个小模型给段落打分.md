# 上下文剪枝：在检索与回答之间加个小模型给段落打分

- 日期：2026-07-07 / 2026-07-21
- 来源：https://www.kapa.ai/blog/how-we-prune-rag-context（kapa，省 68% 上下文降三成成本只慢 0.7 秒）；https://huggingface.co/papers/2607.18213（SWE-Pruner，冻结隐层挂轻量头，token 省 39% 通过率还涨 3.8%）
- 主题：三、提示词与上下文管理

## 这是什么

**2026-07-07**：在检索和回答之间加个又快又小的模型给资料段落打分、扔掉没用的，砍掉约 68% 上下文、成本降三成，只慢 0.7 秒。

**2026-07-21**：在冻结的隐层上挂个轻量头逐行取舍，不用外挂打分模型。token 省 39%，SWE-Bench 通过率还涨 3.8%。

## 可以怎么用

- 如果自己的 RAG/检索流程把大段检索结果原样塞给模型，可以试试加一道「打分-筛选」步骤：用一个小而快的模型给每段资料打分，只留真正用得上的部分，能大幅省上下文和成本，且延迟增加很小（这条材料里是只多 0.7 秒）。
- 上下文剪枝不一定非要外挂一个打分模型；如果技术上可行，也可以考虑在模型自身的隐层上做轻量的逐行取舍，这条材料给出的效果是省 token 的同时任务表现不降反升。
- 两种做法的共同思路是「先筛后喂」，而不是「全塞给模型让它自己找重点」；遇到上下文超限或成本过高的问题，先考虑加一层筛选，而不是急着换更贵的大模型或加更大的上下文窗口。
