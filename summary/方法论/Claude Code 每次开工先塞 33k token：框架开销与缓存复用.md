# Claude Code 每次开工先塞 33k token：框架开销与缓存复用

- 日期：2026-07-13
- 来源：https://systima.ai/blog/claude-code-vs-opencode-token-overhead
- 主题：三、提示词与上下文管理

## 这是什么

Claude Code 每次开工前先塞进 33k tokens，OpenCode 只用 7k。这些 token 全是系统提示、工具定义这类框架开销。文章还测到 Claude Code 的缓存复用差很多，反复重写缓存要多花几十倍 token。

## 可以怎么用

- 理解自己每次用 Claude Code 干活的真实成本时，要意识到有一大块是「开工前」就已经固定支出的框架开销（系统提示词+工具定义），跟具体任务大小无关；如果频繁开新会话做小任务，这部分固定开销占比会更高。
- 如果发现同一个项目/任务反复重跑时 token 消耗异常高，可以怀疑是不是缓存没有被有效复用、导致缓存被反复重写——这类重写的代价可能是正常的几十倍。
- 比较不同 harness/工具（比如 Claude Code vs OpenCode）时，除了看模型本身的能力，也该看框架开销和缓存复用效率这两个容易被忽略的成本维度，它们直接决定同一个任务用不同工具跑下来的真实账单差异。
