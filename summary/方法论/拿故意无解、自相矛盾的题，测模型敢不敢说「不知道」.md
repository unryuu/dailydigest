# 拿故意无解、自相矛盾的题，测模型敢不敢说「不知道」

- 日期：2026-06-20
- 来源：https://arrowtsx.dev/bigger-models/（主文）
- 主题：四、评测与实验设计

## 这是什么

一个反直觉的实测：MIT 协议、可白嫖的开源模型 GLM-5.2，幻觉率 <b>28%</b>，而最大的闭源旗舰 GPT-5.5 是 <b>86%</b>，差了约三倍。数字不是作者自制的，引的是第三方 AA-Omniscience 跑分（这里「幻觉率」指模型答不上来时不说「我不知道」、反而自信编答案的比例）。完整排名（幻觉率从低到高）：GLM-5.2 28%、Opus 4.8 36%、Fable 5 48%、GPT-5.5 86%、DeepSeek V4 Pro 94%。
最扎心的是那个 asyncio 案例：作者给一道故意自相矛盾、根本无解的题，DeepSeek V4 Pro 烧了近 10 倍推理 token，照样自信地给出错误答案；GLM-5.2 花 12 秒、约 800 token 就看穿这题逻辑不成立。作者的解释很刺：这些模型体量太大，压根没学会说「我不知道」，也没学会识别精巧的逻辑谬误。
他的论点不是「小模型更好」，而是「跑分高、体量大，不自动等于靠谱」，提醒大模型的商品化正在模糊「跑分」和「真实世界里的准确性」之间的界线。
（注：这是个人博客，定量数字引自第三方平台，但作者没做统计显著性、定性论据只有 asyncio 一例，属靠谱但不严谨，当一个有意思的信号看。）

## 可以怎么用

- 评测自己常用的模型时，除了常规跑分，专门备一道故意无解/自相矛盾的题（比如逻辑矛盾的 asyncio 需求），看它是硬编答案还是能看穿题目本身不成立。
- 复现要控制变量：均用 high 推理档、temperature 1、同一 system prompt、走同一 API 网关（如 OpenRouter），否则结果不可比。
- 「跑分高不等于靠谱」这个提醒可以用来筛选给团队用的默认模型——体量大、榜单靠前的模型不一定更敢说「不知道」，实际选型时该单独测一下幻觉率而非只看能力榜。
