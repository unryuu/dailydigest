# convolve：把交互轨迹蒸馏成停手规则，不训练就大幅提升弃权

- 日期：2026-06-30
- 来源：https://huggingface.co/papers/2606.28733（主文）
- 主题：四、评测与实验设计

## 这是什么

今天两篇 HF 新论文从相反方向戳同一个钩子：agent 的瓶颈不在参数规模。第一篇做了个 28000 任务的新基准，测「该停手时知不知道停」，结果最强模型的及时弃权召回只有 26.7%，而且更大的模型、更多的推理不仅没救、反而更不会及时停；真正管用的是把交互轨迹蒸馏成一套停手规则（叫 convolve，完全不训练），就能把 Llama-70B 从 26.7% 拉到 57.4%。一句话点题：难的不是 agent 能不能弃权，是知不知道何时弃权。
另一头是 InternScience 的 Agents-A1，一个 35B 的 MoE，在部分长程 agent 基准上自报追平甚至超过 1T 的大模型（GAIA 96.0 对 Kimi-K2.6 的 80.6），靠的是放大任务 horizon、域路由蒸馏加专用基础设施，而不是把参数堆上去。两篇合起来，把「scale 参数」这条主路从需求端和供给端同时否掉。口径要留个尾巴：Agents-A1 是技术报告自评，而且自己也承认 MLE-Bench 这类任务还落后 GPT-5.5 近 29 分，别当已证结论。

## 可以怎么用

- agent 长任务里「不知道何时该停」比「能不能做对」更值得优先解决；评测自己的 agent 流程时，可以专门测一下及时弃权/止损的召回率，而不是只看最终成败。
- convolve 的思路（把过往交互轨迹蒸馏成一套停手规则，不需要重新训练）可以类比迁移到自己的 agent harness：把「该停手却没停」的案例攒起来，提炼成一批规则或 checklist，直接嵌进提示词/流程里。
- 看到「更大模型/更多推理反而更不会停」这条，在给任务调高 reasoning effort 或换更大模型前，先确认问题是不是出在「不知道该停」而不是「算力不够」，调大反而可能适得其反。
