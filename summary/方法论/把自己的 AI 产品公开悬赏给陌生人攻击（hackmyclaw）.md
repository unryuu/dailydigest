# 把自己的 AI 产品公开悬赏给陌生人攻击（hackmyclaw）

- 日期：2026-06-26
- 来源：https://www.fernandoi.cl/posts/hackmyclaw/（主文）
- 主题：五、AI 安全与红队

## 这是什么

有个开发者把自己做的 AI 邮件助手 Fiu（底层是 Claude）挂到网上公开悬赏：谁能骗它把一个装着密钥的文件主动回信发出来就算赢。结果超过 2000 人发了 6000 多封花式攻击邮件，有假装是「未来的你自己」的，有伪造事故应急的，有 4 分钟甩 20 个变体狂轰的，甚至有人把 Anthropic 官方那串触发拒答的测试字符串发来、直接搞瘫了他的处理流水线，但密钥一次都没漏。作者本想证明「给 AI agent 权限很危险」，反被自己的数据打了脸，从此「明显更乐观」。有效防御其实极简：一句硬约束的 system prompt，加一个专门抗注入训练的模型。但他留了个尾巴：这是单个产品、只测了最强的 Opus 4.6，换个弱模型结论可能就变，他也仍然不敢给 agent 任意权限。

## 可以怎么用

- 想验证自己 AI 产品的安全边界，与其闭门造车做内部红队，不如公开悬赏征集真实攻击流量——2000 人 6000 封邮件的攻击密度是自己团队很难模拟出来的。
- 有效防御可以很简单：一句硬约束的 system prompt + 一个抗注入训练过的底层模型，不一定需要复杂的多层防护才能扛住花式社工攻击。
- 悬赏测试的结论要留个尾巴——只在最强模型上测出的安全性，不能直接推广到换用更弱模型时的表现，做同类测试时应注明测试的具体模型版本。
- 把「给 AI agent 权限有多危险」这类假设，用真实攻击数据去验证而不是靠直觉判断，作者本人的态度也因此从悲观转向乐观。
