# summary 接口：日报流程怎么把料喂到这边

目标：以后写日报时顺手把方法论 / 评测人物攒到 summary，不打断日报节奏，攒够了再批量转成正式文档。

分两端：**接收端**（summary，已搭好，你不用动）+ **接入端**（日报流程，你改一处）。

---

## 接收端（已就绪）

- `inbox/方法论候选.md` —— 追加式，一条一段，格式即 scan 条目。
- `inbox/人物候选.md` —— 追加式表格。
- 两个文件顶部都写了格式和纪律，日报 agent 照着 append 即可，不需要脚本。

## 接入端（你在日报流程加这一处）

最自然的钩子是 **`steps/9-收尾.md`**：这时 `daily.json` 已定稿，能干净地判断哪些条目是方法论、哪些作者是评测相关。在第 4 步（更 STATUS）之后、第 5 步（commit）之前，插一步，措辞大致：

> **N. 喂 summary（副产品沉淀）**：扫当期 `daily.json` 的 `deep` / `papers` 分区（旧格式扫 `deep`），把「读者看完能改变做事方式」的方法论条目按模板 append 到 `summary/inbox/方法论候选.md`；当期出现的 LLM 评测 / 模型质量 / 对齐测试方向的作者 append 到 `summary/inbox/人物候选.md`。判断不准就宁可收进来标存疑。本步只追加、不策展。

因为第 5 步 commit 的 `git add` 目前只加 `reports/<date> sources STATUS.md`，要让 inbox 的追加也进版本库，把 `git add` 那行补上 `summary/inbox`（或者你不在意 summary 的版本管理就不加，文件照样在本地）。

零侵入备选：如果不想动日报流程，就什么都不加——方法论内容绝大多数已进 `daily.json`，summary 这边随时可以自己跑一次「增量 scan」，只扫上次处理日期之后的新 `reports/<date>/`，用 `work/prompts/scan.prompt.md` 派 subagent 即可，事后补也不丢东西。代价是人物的「当天产出」得从 daily.json / manifest 回捞，不如当场记准。

## 攒够了怎么转正（主 agent 批处理）

1. **方法论**：读 `inbox/方法论候选.md` 全部新条目 + 现有 `方法论/` 文件名（避免重复选题），按 `work/prompts/curate.prompt.md` 的精神合并同题、筛掉薄条目、归到 README 现有 11 个主题下，再按 `work/prompts/write-method.prompt.md` 派写手写成 `方法论/` 下的独立文档。写完更新 `README.md` 索引，清空 inbox 已处理条目。
2. **人物**：读 `inbox/人物候选.md`，按人合并进 `人物/作者名单.md` 对应分类（同名追加产出行），清空 inbox。
3. 转正是批处理，别一条条来——攒到十几条或要写博客时做一次即可。

## 现有资产（复用别重造）
- `work/prompts/` —— scan / curate / write-method 三份提示词，就是这次建库用的，转正直接复用。
- `work/scan/batch-1..6.md` —— 首次建库（06-12~07-29）的逐期原始记录，含所有被砍条目，回收时先翻这里。
