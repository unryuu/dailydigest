# 步骤 1 · 定日期 + 派 scout 扫源

## 定日期
- 目标日期 = 上一期 + 1（看 STATUS 顶部）。有时候过了零点才提的，仍算前一天，别按系统钟多跳；不确定时，问用户具体日期。
- `mkdir -p reports/<date>/work/digests`

## 派 scout
派 1 个 general-purpose subagent，**前台跑**。派活 prompt 带上：
- 让它先读 `roles/scout.md`（红线、29 源、推特慢抓规矩、manifest 结构全在里面）
- 目标日期 `<date>`，manifest 写入路径 `reports/<date>/work/manifest.json`
- **防重复主线 + 近期已报赔率**：照抄 STATUS「防重复」节给它，同一主线只收新进展，报过的市场别再列（概率变化 >10 点除外）
- **近 3 期已报清单**：跑 `uv run scripts/recent_titles.py <date>` 把输出附进派活 prompt——同一事件换链接、换转述人也别再收；拿不准的可以收，但在 why 里标「疑与 X 日已报重叠」交定牌裁决

## 验收
- scout 回一句概要：几组精读 / 几雷达 / 几乐子 / 几赔率 / 几个抓取失败。
- 跑 `uv run scripts/check_dup_urls.py <date>` 查 manifest 撞往期：精读/雷达/乐子撞了就丢；赔率撞了看脚本给的上次日期和概率，隔得久或变化大可再报，否则丢。如果当天的赔率没有新鲜东西，可以放宽为“非AI + 热门 + 有乐子”抓几个。
- X 消息源全 403/429 → 如实记 fetch_failures，别当场折腾换镜像（记进收尾 report，连挂几天再跟用户议）。

产出：`reports/<date>/work/manifest.json`（查重后的干净版）。下一步 → `steps/2-定牌.md`
