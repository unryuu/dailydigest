# 步骤 1 · 定日期 + 派 scout 扫源

## 定日期
- 目标日期 = 上一期 + 1（看 STATUS 顶部）。有时候过了零点才提的，仍算前一天，别按系统钟多跳；不确定时，问用户具体日期。
- `mkdir -p reports/<date>/work/digests`

## 先机械扫源（默认通路）
跑：

`uv run scripts/collect_sources.py <date>`

脚本一次扫 33 源，普通请求失败会自动用 Chromium 兜底，并先做时间窗、seen、往期已发 URL 和赔率市场的机械查重。产出：

- `reports/<date>/work/scout_candidates.json`：给 scout 的标准化候选。
- `reports/<date>/work/scout_fetch.json`：33 源抓取诊断；失败源也在这里。

脚本不写 seen、不写 manifest。跑完先看末行候选数和失败数；候选为 0 或脚本崩溃才走下方「备份通路」，不要让 scout 重抓一遍。

## 派 scout 离线分桶
派 1 个 general-purpose subagent，**前台跑**。它不联网，只读上面两份 JSON。派活 prompt 带上：
- 让它先读 `roles/scout.md`（红线、33 源、推特慢抓规矩、manifest 结构全在里面）
- 明说「走默认离线通路：不自己抓网页，不派 subagent」
- 候选路径 `reports/<date>/work/scout_candidates.json`，诊断路径 `reports/<date>/work/scout_fetch.json`
- 目标日期 `<date>`，manifest 写入路径 `reports/<date>/work/manifest.json`
- **防重复主线 + 近期已报赔率**：照抄 STATUS「防重复」节给它，同一主线只收新进展，报过的市场别再列（概率变化 >10 点除外）
- **近 3 期已报清单**：跑 `uv run scripts/recent_titles.py <date>` 把输出附进派活 prompt——同一事件换链接、换转述人也别再收；拿不准的可以收，但在 why 里标「疑与 X 日已报重叠」交定牌裁决

## 备份通路（统一脚本不可用时）
保留旧实现：让 scout 自己按 `roles/scout.md` 的「备份通路」逐个读取 33 个 `meta.json`，依次 `curl -L`；失败再跑 `uv run python browser/fetch_browser.py list --slug <slug>`；X 源串行且间隔 ≥4 秒。它自行做 seen / 时间窗过滤并直接写 manifest。

只有默认脚本实际失败时才启用，不要两条通路同时扫，避免重复耗时和互相覆盖。

## 验收
- scout 回一句概要：几组精读 / 几雷达 / 几乐子 / 几赔率 / 几个抓取失败。
- 跑 `uv run scripts/check_dup_urls.py <date>` 查 manifest 撞往期：精读/雷达/乐子撞了就丢；赔率撞了看脚本给的上次日期和概率，隔得久或变化大可再报，否则丢。如果当天的赔率没有新鲜东西，可以放宽为“非AI + 热门 + 有乐子”抓几个。
- X 消息源全 403/429 → 如实记 fetch_failures，别当场折腾换镜像（记进收尾 report，连挂几天再跟用户议）。

产出：`reports/<date>/work/manifest.json`（查重后的干净版）。下一步 → `steps/2-定牌.md`
